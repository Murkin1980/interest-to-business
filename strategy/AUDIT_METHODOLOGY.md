# Internal audit method v0.2 — framework, not new BD code

## 1. Problem intake
Сформулировать процесс, участника, момент возникновения потери, частоту и источник информации. Бесплатная первичная беседа — не глубокий аудит.

## 2. Interview evidence
Использовать существующие BD intake/interview; по одному вопросу, без наводящих формулировок. Фиксировать факт / мнение / предположение / неподтверждённое утверждение, дату и согласие на использование материалов.

## 3. Current-state map
Триггер → действия → ручные передачи → инструменты → задержки → ошибки → результат. Для каждого узкого места — пример, объём и первоисточник.

## 4. Opportunity selection
Оценивать эффект, срочность, сложность, обратимость, риски для данных и доступность метрик. Запрещено выдавать гипотезы ИИ за проверенные факты.

## 5. Minimum experiment
Один ограниченный процесс, владелец, ожидаемый результат, baseline, срок, допустимые затраты и STOP-критерий. Сначала пробовать шаблон/ручное изменение, затем автоматизацию.

## 6. Delivery
Аудит выдаёт: краткое описание проблемы, as-is, таблицу доказательств, 2–3 альтернативы, предположения экономического эффекта, рекомендуемый пилот и то, что пока неизвестно.

## 7. Outcome
Измерить after, зафиксировать стоимость работ, побочные эффекты и решение клиента. Публикация кейса — только при отдельном согласии и обезличивании.
